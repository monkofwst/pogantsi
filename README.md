# PARALLAX v0.1.9

Актуальные инструкции по новым осям и запуску: START_HERE.md. Ниже сохранена справка о прежнем режиме вкладов.

X = contribution_G2: устойчивые спутники.
Y = contribution_G3: повторяющиеся цепочки и циклы.
Z = contribution_G4: всплеск активности с быстрыми возвратами.

Цвет точки определяется target. Оси имеют фиксированную шкалу 0–1; произвольные x/y/z и прежние оси по числу перелётов больше не используются. Линейный перевод в координаты сцены одинаков по всем осям: (значение − 0,5) × 12. Инспектор показывает исходные значения G2–G4, а не служебные координаты сцены.

## Запуск

Windows: запустите start_windows.bat при установленном Python 3.
Linux: выполните bash start_linux.sh.
Вручную: python3 -m http.server 8765, затем откройте http://localhost:8765.

Открывать index.html через file:// не нужно: автоматическая загрузка CSV требует локального HTTP-сервера. Обработка остаётся в браузере; интернет и npm не требуются. После замены старой версии обновите страницу через Ctrl+F5.

## Загрузка результатов проекта

Импортируйте users_scored.csv из scoring_runs/<отпечаток>/ через кнопку «Импорт CSV». Файл принимается без переименования столбцов и предварительного расчёта координат.

Основной контракт:

| Поле | Использование |
|---|---|
| person_id | ID профиля |
| target | Цвет, фильтр и рейтинг |
| contribution_G2 | X |
| contribution_G3 | Y |
| contribution_G4 | Z |
| G2, G3, G4 | Режим флагов 0/1 |
| reliable_segments | Число пригодных сегментов в инспекторе |
| core_mechanisms | Число основных механизмов |
| matched_hypotheses | Пояснение профиля |

Поддерживаются альтернативные названия passenger_id и anomaly_score. Если contribution_G2/G3/G4 отсутствуют, координатами становятся непосредственно G2/G3/G4. Числа должны находиться в диапазоне 0–1; true/false также допустимы. Старый файл только с x/y/z не принимается. Пустые значения не заменяются нулями: некорректные строки и повторные ID пропускаются с указанием их числа.

Дополнительные поля cluster_id, flight_count, unique_destinations, confidence, first_seen, last_seen, top_reason используются при наличии. Отсутствующая уверенность или число направлений отображаются как «—».

## Если имеется только Parquet

Используйте Python из окружения аналитического проекта, где установлен duckdb:

```bash
python prepare_profiles.py /полный/путь/users_scored.parquet --output data/passengers.csv
```

Можно указать папку частей Parquet, полученную при подготовке проекта для Git. Скрипт сохраняет все профили, проверяет ID и диапазон осей/target и экспортирует только нужные приложению колонки. Этот вызов заменяет демонстрационный data/passengers.csv вашим набором. Альтернатива — --output profiles.csv и ручной импорт готового CSV. Браузер читает CSV; прямой импорт Parquet не добавлен.

## Управление

«Вклады»: численные значения contribution_G2/G3/G4. «Флаги»: G2/G3/G4 в виде 0/1; при отсутствии флагов используется признак ненулевого значения оси. В обоих режимах соответствие X/G2, Y/G3, Z/G4 сохраняется.

Мышь вращает сцену, колесо меняет масштаб. Клик по точке или строке рейтинга выбирает профиль. Escape и × снимают выбор. Порог фильтрует точки по target. Цвет и рейтинг не участвуют в расчёте координат.

Равные координаты отображаются в одной позиции. В частности, профили с нулевыми вкладами совпадут в логическом начале координат. Случайное смещение точек не применяется. Для выбора совпадающих профилей доступен рейтинг с поиском по ID. В режиме флагов возможно только восемь положений.

## Хроника

Файл data/flights.csv загружается отдельно при открытии истории. Он использует passenger_id, flight_date и дополнительные event_id, departure_hour, origin, destination, source. Для собственных профилей загрузите соответствующий файл событий: демонстрационные события связаны только с демонстрационными ID.

## Демонстрационные данные

В комплекте 100 000 профилей и 300 000 связанных событий. Генератор data/generate_demo.py теперь создаёт демонстрационные G2/G3/G4 и вклады, из которых вычисляет демонстрационный target. Это искусственные значения для демонстрации интерфейса; механизм проверки реальных исходных таблиц остаётся в аналитическом проекте.

Повторное создание демо требует numpy и pandas:

```bash
python data/generate_demo.py --out data --passengers 100000 --seed 42
```

Визуализация использует Canvas 2D. Скорость отображения полного набора зависит от компьютера и браузера. Загрузка больших CSV требует оперативной памяти.
